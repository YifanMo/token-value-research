# Crypto3D 与本地 P/E、P/S：缺什么，怎样借鉴

核查日期：2026-10-03（北京时间）。本地行情快照仍为2026-10-02，金额采用截至2026-10-01的完整UTC日；没有为使结果一致而改行情或补利润。参考站证据抓取于2026-10-02 18:52–18:54 UTC，后续在线内容可能改变。

**可以借鉴。之前本地只展示完整净利润口径的P/E，没有展示现有回购／销毁统计就能计算的倍数，这是展示和定义的问题，不是所有数据都拿不到。** 现在主表默认提供参考算法，并可切换独立收入与净利润；各单元格列出分母、窗口、年化过程及保存响应。

## 1. 同叫 P/E，分母不同

| 指标 | 参考站主表实际算法 | 之前本地采用的算法 | 当前处理 |
|---|---|---|---|
| P/E | 市值÷年化持币人回报；页面实际用`100 / shareholder_yield_percent` | 市值÷同窗完整净利润 | 新增“参考P/E：回购／销毁统计倍数”；独立净利润P/E继续单列 |
| P/S | 市值÷年化收入统计；页面实际用`100 / total_yield_percent` | 市值÷经语义核验的独立协议所得收入 | 普通收入保留相同算法；UNI另外显示“兑换估值分母”，不当成营业收入 |
| Net Inc | 展示列；不参与主表P/E的除法 | 需要成本完整、同窗同范围的有来源记录 | 不把参考站此字段直接导入为已核实净利润 |

市值100亿美元，一年回购10亿美元，就能得到10倍的回购金额倍数。即使成本账还没有取得，仍能计算这个比例；它不能据此证明一年经营净利润也是10亿美元。这个区别应通过列名和来源说明解决，不应把已有统计全部隐藏。

2026-10-03补充澄清：“读取同一份快照”不等于“使用同一个金额”。两种口径共用市值、FDV、窗口与年化步骤；参考P/E用`holders.usd`，净利润P/E需另取`financials.net_income_windows`。P/S通常没有两种除法：当前30天HYPE、PUMP、JUP、RAY两边都用同一个`revenue.usd`，所以结果相同；UNI的区别是是否接受兑换估值作为收入分母。HYPE参考P/E与P/S相同来自当前上游H与R相同，不能推断完整经营成本为零。网页选择器改称“指标口径”，参考P/E主列改称“回购／销毁倍数”。

已保存的[参考网页源码](evidence/crypto3d/equity.html)中，tooltip解释P/E为持币人回报倍数，渲染代码用`100 / tevYield`与`100 / earningYield`。HYPE与UNI的[汇总JSON](evidence/crypto3d/all-protocols.json)有这些字段。当前五币中只收录HYPE、UNI；26条主表记录不包含PUMP、JUP、RAY。未收录不表示项目收入为零。

## 2. 用本地已有数据重算

统一30天金额期间2026-09-02至2026-10-01；7/30/90天年化是历史速度参考，金额乘365再除以窗口天数。完整365天使用年度总额。上行用流通市值，下行用所选FDV；下表FDV采用CoinGecko供应商字段。

| 项目 | 参考P/E：流通 / FDV | 参考P/S：流通 / FDV | 分母是什么 |
|---|---|---|---|
| HYPE | 30.02x / 128.90x | 30.02x / 128.90x | 分给AF的收入＋费用销毁估值；R与H在当前API方法中相同 |
| PUMP | 9.35x / 16.71x | 4.49x / 8.01x | P/E用已销毁代币估值；P/S用剔除重复移动端后的协议收入 |
| UNI | 30.44x / 43.21x | 30.44x / 43.21x | 两个原始字段均是Firepit费用兑换UNI的估值；独立费用收入未核 |
| JUP | 28.78x / 59.49x | 14.38x / 29.72x | 收入及按比例计算的回购额度；业务统计覆盖重叠尚待去重 |
| RAY | 9.22x / 18.97x | 5.77x / 11.87x | 收入及按分配比例计算的回购额度；尚未逐笔核现金执行 |

例：PUMP的30天H为23,922,255美元，年化291,054,102.50美元；流通市值约27.22亿美元，除以该金额得到9.35x。R为49,859,813美元，年化606,627,724.83美元，所得P/S为4.49x。这两项均有输入，不要求先编造一份成本账。全部精确数与请求来源在[data/dashboard.json](../data/dashboard.json)，计算在[web/core.js](../web/core.js)。

**UNI参考P/S是兑换估值倍数。** 独立收入模式仍显示待核；不能因为有数字就宣称已拿到独立营业收入。PUMP365天缺5月21日Mobile子项，归一化R仍未知，参考P/S也留空。365天H有原始统计，所以参考P/E可显示历史倍数，但窗口跨库存销毁事件，必须保留“历史统计，库存事件未对账”提示；持续销毁收益率仍停止年化。参考倍数不改变实际供应、现金回购或经常性收益的结论。

## 3. 为什么没有直接照搬它的数值

| 30天算法 | 本地参考P/E / P/S | 参考站保存字段复算P/E / P/S | 需要核对的差别 |
|---|---|---|---|
| HYPE | 30.02x / 30.02x | 17.30x / 17.30x | AF统计范围不同；参考短窗收益率沿用旧市值计算结果，当前市值未同步复算 |
| UNI | 30.44x / 30.44x | 144.93x / 144.93x | 主网dead转账与本地多链Firepit兑换记录不同；旧币价、台账截止日及市值时点不同 |
| PUMP / JUP / RAY | 可用本地同窗输入计算 | 未收录 | 本次没有参考主表记录可逐项目照搬 |

这些是不同输入产生的差异，不能解释为同一项目在同一时点的“便宜或昂贵”，更不能直接用于价格变动归因。

### HYPE 的证据

参考汇总记录市值19,496,307,623美元，年度R及Net Inc均为772,987,701美元；年度H为R的99%，即765,257,823.99美元。其年度预计算收益率给出P/E约25.48x、P/S约25.22x；若P/E真以Net Inc为分母，应得到25.22x，而不是25.48x。

30天预计算收益率5.78%得到17.30x。记录的30天收入34,979,838美元，按当前19,496,307,623美元市值重算收入倍数却为45.81x。5.78%与旧市值约73.68亿美元相符，这是不同字段时点混合的证据，不应复制为当前行情倍数。

[HYPE保存snapshot](evidence/crypto3d/hype-snapshot.json)的运营成本与增发成本为空，备注明确说明无LP／运营成本模型，100%“净利率”为非经营性利润口径。它可用于研究该网站的统计定义，不能填补完整经营成本账。[HYPE/PUMP完整复现](evidence/crypto3d/hype-pump-findings.md)

### UNI 的证据

参考站配置使用Etherscan V2查询Ethereum UNI转到dead地址的记录，排除单笔≥1,000万UNI的一次性事件；现有台账含不同转出地址，未证明全部由Firepit同一流程产生。验证金额4,580,003 UNI按旧价4.01美元估值，得到18,365,812.03美元，被用于收入和净利字段。

参考汇总目前市值56.16亿美元、币价8.98美元，但这份历史估值仍沿用4.01美元；预计算年度收益率0.327%得到305.81x。30天比例0.69%得到144.93x，不能把它与daily里的当期金额及当前市值任意拼接重算。公开烧币台账最后一条日期为2026-08-10，验证范围止于8月1日，汇总更新时间却标10月2日。主网台账还没有覆盖本地适配器统计的多链兑换记录。[UNI专项核查及逐文件清单](crypto3d-uni-review.md)、[原始manifest](evidence/crypto3d-uni/manifest.json)

## 4. 两边的数据获取链

本地：公开DefiLlama父协议逐日F/R/H响应＋CoinGecko市场快照 → 按完整UTC日选窗口 → 按已核源码去重并标语义 → 写dashboard及响应哈希归档 → 浏览器加总、核哈希 → 同窗计算倍数。机制、解锁政策与未核项分别人工登记，不通过默认成本率生成净利润。完整现金回购成本和供应执行量仍需独立链上台账。

参考站：主表HTML → `all-protocols.json` → 各项目`daily/{key}/latest.json`覆盖非空顶层字段及非空metrics → 缺部分展示值时再从snapshot补。嵌套`latest_record`不会自动提升为主表市场字段。UNI另有配置、dead转账台账及校验记录。7/30/90天使用预计算收益率，缺失可回退365天；Rev及Net Inc展示列始终365天。**看起来是同一行的数据，也不保证所有字段是同一个窗口或同一次更新。**

## 5. 真正还缺什么

- 五项目同窗同范围的完整经营成本与净利润。参考站已经核查的HYPE、UNI记录也没有补齐这项。
- UNI独立费用资产收入与现金兑换成本；“烧了多少币×币价”不能同时证明这两者。
- PUMP年度去重缺日；JUP业务覆盖重叠；RAY额度到现金执行的逐笔对账。这些缺口保留在对应统计旁。
- 各项目实际回购、销毁、解锁分发和增发台账。P/E、P/S有数不等于已验证净通缩。

评估顺序是：先显示已有输入能计算的明确口径，再列待取得的独立数据。完整净利润缺失只阻止独立净利润P/E，不再阻止展示回购／销毁统计倍数。
