# 可重复使用的代币价值评估框架

研究基准：2026-10-02（北京时间）；统计口径于2026-10-03复核。所有价格和流量须另存实际来源时间。框架的核心是：**收入流量、代币库存、供应权限分别记账，最后在相同窗口对账。**

## 1. 先确定持币人拥有什么

经济回购政策不自动产生股权、现金分红请求权或金库索取权。每个项目先填清楚收入主体、受益代币、治理/多签/系统权限、可否撤销或更改、承诺期限、代币最终去向。状态至少分为公告、提案、投票通过、执行、目标链生效、最终到账；任何一个上游状态都不能代替下游。

| 最终去向 | 当期买入需求 | 经济有效总量 | 自由流通 | 必须验证 |
|---|---|---|---|---|
| 回购并真burn / 不可动用系统地址 / dead地址 | 需核实市场成交；searcher可交库存 | 减少经济有效供应；不一定减少合约totalSupply | 仅来自流通的部分减少 | burn指令、权限、取回路径、资金来源 |
| 固定期限锁仓 | 若已成交则有 | 不减少 | 暂时减少，定义要一致 | 到期、提前退出、可升级权限 |
| 金库持有 | 若已成交则有 | 不减少 | 可能减少；供应商未必扣除 | 钱包归属、处置权、后续转出 |
| 稳定币/现金分红 | 不必有回购 | 不减少 | 不直接改变 | 哪些持有人能领取、领取成本 |
| 本币质押奖励 | 可能只是重新分配本币 | 可能增发，也可能来自已有储备 | 未流通库存发给用户可能增加 | 新mint与储备释放分开，不当现金收益 |

经济不可用并不等于完全没有治理风险。HYPE AF 的销毁确认、UNI dead转账、PUMP SPL burn分别保存技术路径，而非用一个“burn”标签抹平差别。[HYPE官方费用](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees)、[UNI费用架构](https://developers.uniswap.org/docs/protocols/protocol-fee/overview)、[PUMP政策](https://pump.fun/pump-token)

## 2. 重建收入瀑布

```text
用户付费 F
  − LP / lender / builder / creator / referral / partner / cashback 的分成 S
  = 协议可归属收入 R
  − 开发、维护、运营、审计、增长和其他成本 O
  = 可持续可分配资源（资料不足时不称净利润）

R中的代币预算 A
  → 实际支付回购现金 C
  → 实际取得代币 Q
  → burn / lock / treasury / 再分发
```

这里的 R 必须是经源码和资产口径核验的协议收入，**不能只因字段叫 `dailyRevenue` 就代入**，也不是完整会计利润。各API实际方法不同：PUMP的R是扣产品分成后的收费统计，HYPE的R已是AF分配加HIP-1销毁估值；UNI当前R字段则复制Firepit兑换UNI的美元估值，独立费用收入仍未知。将原API字段与可用于财务计算的R分开保存；收入未独立取得时不计算独立收入口径P/S、收入分成率或以差额推导外部成本。参考算法的估值字段倍数另行标注，见5.2。[UNI固定源码核查](flow-uni-notes.md)、[HYPE/PUMP流向核查](flow-hype-pump-notes.md)

数据源文档另把非持币人金库所得称 Protocol Revenue，把 Token Holder Revenue 单列；界面“协议留存收入”不能被误读为其狭义 ProtocolRevenue。现金回购与收入往往在不同日，不能强求每一天 `C/R` 等于宣传比例。[DefiLlama定义](https://docs.llama.fi/analysts/data-definitions)

保存两个比例：`A/R`（可归属收入进入代币多少）与 `A/F`（用户支付多少最终指向代币）。宣传99%、50%、12%只有同时写分母才有可比性。底层DEX手续费不能作为聚合器收入再记一次；父协议和子产品不可重复加总；长尾币美元标价不等于可变现现金。[公开适配器](https://github.com/DefiLlama/dimension-adapters)

父级接口也可能包含重复子项。2026-10-03核对发现HYPE的HLP费用已包含于Perps/Spot用户费用，却再次进入父级Fees；PUMP Mobile的发行/Swap交易也重复进入父级费用与收入。仅在元数据方法与已核规则一致、每日所需子项齐全并与父级对账时剔除重复行，分别保存原始总额、剔除额和去重总额；上游已去重时不再次扣。父级`doublecounted=null`不代表所有子项均不重复，PUMP独立Mobile接口明确为true。方法变化、缺项或算术不匹配时保留未知。[HYPE分母修正及未对上金额](hype-fee-audit.md)、[PUMP逐日去重与归档证据](flow-hype-pump-notes.md)

PUMP同窗30天去重F=$159,514,205、R=$49,859,813，R/F=31.26%；burn估值/R=47.98%仅为不同性质统计的比值，不能证明50%现金回购兑现。Terminal的R按收费减cashback/referral钱包支出，可出现真实负项；保留带符号合计，不将负数当缺失或截成0。365天的Mobile首日2026-05-21仍缺记录，不能把已知子项之和称完整去重年收入。

还要分清：真实付费不等于真实外部需求。激励刷量、creator循环交易、短期补贴和协议自身mint形成的会计收入需要排除；收入减本币激励后的资源也不等于已扣所有经营费用。成本不完整时不计算净利润P/E；独立收入不完整时独立收入口径P/S也保留未知，不能用兑换/销毁估值补齐。已有持有人统计可以计算明确分母的参考倍数。

## 3. 用业务指标判断持续性

| 问题 | 连续跟踪的量 | 常见误判 |
|---|---|---|
| 谁付钱，为什么付？ | 分产品实际手续费、付费用户、留存 | 把成交额、TVL或funding全部当收入 |
| 收入是否由单一热潮贡献？ | Meme/杠杆/链别/客户集中度 | 把高费率Meme收入视为均匀分散 |
| 收入增长来自量还是提价？ | 真实volume、有效fee rate、协议take rate | 只看美元收入，不看费率和币价 |
| 用户是否付完就走？ | 活跃及付费用户、重复使用、流动性深度 | 一个地址当一个自然人 |
| 牛市消失后还能赚多少？ | 7/30/90/365天、低迷季度、份额 | 把最好一周年化成稳定利润 |
| 补贴后还有多少资源？ | 激励、增长预算、gas/桥接/变现成本 | 本币奖励既当收入又不扣稀释 |

基础情景用90日与365日交叉看，30日显示趋势，7日只看短期变化。压力情景至少令资金资源降至基线的75%、50%、25%，同时改变买入均价和释放量。收益率高但资金脆弱、权限可撤回、流通释放未知时，投资判断应保持条件式。

## 4. 三种供应定义与两张净变化表

每次保存：链上已铸 `contract_total_supply`、含授权但未铸储备且扣经济不可用币的 `economic_effective_supply`、供应商 `reported_circulating_supply`，以及按钱包规则定义的 `tradable_float`。初始分配、当前钱包余额、未来归属、可领取、已分发、转入交易所、已售出各列保存。团队初始占20%不能称团队现在仍持有20%。

UNI送dead不降低原合约totalSupply；HYPE预留但未铸奖励可能早已在经济分母内；JUP/RAY金库币可能已被供应商扣除，也可能仍被包含。扣回购金库前必须先核circulating排除项，不能二次缩小估值分母。[UNI原合约](https://github.com/Uniswap/governance/blob/ab22c084bacb2636a1aebf9759890063eb6e4946/contracts/Uni.sol)、[HYPE分配](https://hyperfnd.medium.com/hype-genesis-1830a4dc2e3f)

```text
经济有效总量变动
  = 新增经济供应权利（超过已纳入分母的储备） − 全部永久经济销毁

链上已铸总量变动
  = 实际mint − 真正使合约/mint supply减少的burn
  （dead转账不扣；从已计经济储备mint仍会影响此表）

自由流通变动
  = 首次进入流通的解锁 + 未流通储备奖励 + 金库向外净释放
    + 新增经济供应进入流通
    − 从流通退出的永久销毁 − 净新增不可交易锁定/金库留存
```

各项互斥：同一奖励若是储备mint，不能又记一次“新经济供应”和一次“奖励”；已计circulating的ASR分发不能重复增加reported circulating，但可改变tradable float。未分发的解锁资格不是当期流通；已解锁团队继续卖出会改变持有人，却不再增加circulating。

只有类别完整、日期完整且去重后才能输出已核实净通缩/通胀。本次五项目完整未来12月台账均未取得；这不意味着未来数据完全拿不到。当前仪表盘已经把可取得的合约排期、第三方归属模型、奖励速度情景和已到期未领取余额逐项展示。可输出“总有效供应下降，但自由流通可能上升”的条件判断，不因不完整而把未知填0。

**净供应变化不是total supply。** total supply是某时点存量，净变化是期间差额。未来期末有效总量 = 当前有效总量 + 新增经济供应 − 永久经济销毁；已有币解锁只可能影响流通，不自动增加总量。未来期末自由流通 = 当前自由流通 + 各类首次释放 − 从流通退出的币。用供应商circulating作为代理时，必须保留它和实际可交易量的差异。

未来数据保存在 `data/supply-forecasts.json`，以人工复核日为证据时间，窗口用UTC日期 `(as_of, as_of+N天]`。逐日事件只在已列明覆盖期内加总；覆盖期之外未知，不输出假零。线性或年率外推是情景，不能冒充逐日合约排期。已到期未领取余额是期初可释放库存，不计为未来“新到期”，但在评估卖压时不能漏掉。权限上限不计入默认增发，替代模型共享同一分配池时不能相加。

证据分层：官方已批准计划/原合约参数、第三方模型、二级报道拟执行、当前速度外推、情景假设、未核实。参数可更改、allowance可撤销、奖励vault可能不足时，即使代码可计算也不保证未来一定转出。RAY staking按slot发放，接口每秒值用了2.5slot/秒假设；未来奖励还受网络slot速度、调参、补资影响。

供应模板在 `data/supply-ledger.template.json`。`web/core.js` 的 `ledger` 接受经济总量口径，`knownComplete=false` 或任意必填项未知时返回待核。它不替代链上mint/权限审计。

## 5. 估值与收益率

```text
MC = 同时点价格 × 供应商circulating（或直接使用其reported MC）
主表FDV = CoinGecko的fully_diluted_valuation原值，保留来源口径
数据源总量参考估值 = 同时点价格 × CoinGecko的total_supply
初始供应参考估值 = 价格 × 初始分配量（不是永久上限，也不假设被烧币会恢复）

流量年化 = 同窗经常性流量 × 365 / 窗口天数
实际回购支出收益率 = 年化实际现金回购 / MC或FDV
持续销毁价值收益率 = 年化收入支持的经济销毁价值 / MC或FDV
现金分红收益率 = 年化实付现金分红 / MC或FDV
资金捕获代理收益率 = 年化holder proxy / MC或FDV
```

主表固定使用CoinGecko的FDV，不再通过三种估值选择器改变分母。页面上方总结表显示研究代币总数并始终保留全部代币；其下的“查看全部代币的未来供应对比”默认折叠，展示固定未来30/90/365天的部分计划或估算。再下方统一控制条提供7/30/90天、1/3/5年快捷项及自定义起止日期，右侧为代币下拉选择：窗口同时更新主表、收入去向图、历史图和当前结论，下拉仅决定其后显示哪个代币的详情，不过滤主表。自定义含首尾两个UTC日，闰年按实际366天年化；3/5年快捷项为1095/1825天。点击主表对应项目行可同步下拉选择；收入去向图内不再重复日期或代币按钮。后两种供应量参考估值在当前代币“FDV与供应量估值”折叠详情中查看，不参与主表倍数与收益率。

任意历史窗口先校验本次归档响应的哈希，再按UTC日、相同去重和库存事件规则重新聚合；缺日不以部分总额代替完整总额，协议有记录以前不补政策零。历史回看采用当期流量和当前估值，不是把今日市值冒充当年市值；供应快照、未来排期仍采用当前研究日，事件对照仍采用各自固定日期。收入图在90天以内按日、较长期间按月加总，首尾月只含所选日期，缺日断开。价格图用同一可用日期归一化，缺日断开。

收入API完整可用历史不再截成最近两年。价格近一年采用CoinGecko，更早日期由DeFiLlama coins API单独补充，从2020-01-01起按7币×70日分块；UTC零点±1小时匹配并保留实际时间戳，不当作交易所收盘价，不做缺日插值。历史覆盖的实际起止、中间缺日及每块保存响应、真实请求、哈希、抓取时间均保留，可从页面来源区展开核实。协议或代币尚未存在的年份不创造历史记录。[各币实际起点与采样说明](history-data.md)

采集器 `scripts/refresh.py` 的 `remaining_supply_fdv` 实际是 `current_price × total_supply`，两项均来自同次CoinGecko行情响应；它未使用独立链上mint供应，未自行扣dead、AF或回购金库，也未完成经济有效供应审计。因此不能只凭这个字段名就称其为“已核实当前经济有效总量”。`original_cap_fdv` 实际是同一价格乘 `profiles.initial_supply`，不是接口 `max_supply`。原始字段名为兼容归档保留，界面使用具体计算名称。

`fully_diluted_valuation`、`total_supply`、`max_supply`在CoinGecko接口中分别提供；本工具保留各字段，不假定供应商FDV一定等于显示价格乘最大供应量。当前快照五项目的供应商FDV与价格乘total_supply接近但不完全相等，更不能据此证明未来供应上限或解锁计划。[CoinGecko行情字段文档](https://docs.coingecko.com/reference/coins-markets)

这四种收益率不可混名。PUMP每日burn数量×当日价格，HYPE费用分配+HIP-1直接burn估值，UNI的Firepit兑换UNI估值，JUP/RAY政策预算，都不自动等于实际回购花费。UNI兑换估值也不能自动称已收协议费或已最终主网burn。代理允许筛选，但不能伪装为审计过的现金收益。[适配器源代码](https://github.com/DefiLlama/dimension-adapters)、[UNI统计方法](flow-uni-notes.md)

一次性金库库存销毁不产生外部现金；历史回购存量后来burn，现金只在买入时记一次。尚未拆分stock burn的窗口不算经常性年化；跨政策窗口不把现在的永久burn属性套回过去。UNI2%权限若未行使不当实际增发，另设治理压力项；无限潜在增发代币不存在一个确定永久终态FDV。

合成净吸收率只是模型：`(预算 / 未来买入均价 − 未来自由流通新增币数) × 未来买入均价 / 当前MC`。这不是总量通胀率，也不是持币者现金收益；真实供应量使用枚数台账。缺完整释放量则不判净结果。锁仓/金库保留在情景中只能称潜在流通吸收。

公平估值阈值可以反推：`可持续永久捕获预算 / 所需收益率` 得到可承受的估值，所需收益率由收入波动、稀释、治理和流动性风险决定，而不是统一选5%就叫便宜。运营成本未知时不把收入倍数写成净利润P/E；参考倍数须明确统计分母。

### 5.1 表格中的收入、持币者回报与项目净利润倍数

主表固定并排显示“协议收入倍数 P/S”、持币者回报倍数和项目净利润P/E，不再通过选择器切换两组指标。三项采用相同的估值与时间窗口，但分母分别是未扣完整经营成本的收入统计、指向代币的回报统计、项目净利润。“持币者回报”并非持币者已经到手的现金利润；回购、销毁或尚未兑现的分配预算必须保留各自性质，也不能据此假设项目净利润与holder统计相等。

| 指标 | 公式 | 当前数据边界 |
|---|---|---|
| 协议收入倍数 P/S | 流通市值 ÷ 年化收入统计；下行另列CoinGecko的FDV ÷ 同一金额 | 使用归一化`revenue.usd`并注明数据性质，未扣完整经营成本；UNI为兑换估值倍数，其独立协议收入P/S仍未知；不是用户总手续费或已审计营业收入 |
| 持币者回报倍数（参考站称P/E） | 流通市值或FDV ÷ 同窗年化回购、销毁或分配统计 | 使用完整`holders.usd`；各项目可能是费用分配、预算或代币估值，不代表持币者实收现金或项目净利润 |
| 项目净利润P/E | 流通市值或FDV ÷ 同窗年化净利润 | 五项目当前均未接入净利润数据，快照无净利润记录；不表示已有净利润被校验拒绝，不用收入或回购金额代替 |
| 协议收入占手续费 | 同窗经核验R ÷ 去重后的F | 仅在确认为收费收入时称分成率；UNI独立R待核；不是净利率或毛利率 |
| 回购 / 销毁统计占收入 | 已注明性质的同窗holder统计 ÷ 经核验R | 相同现金口径才可称实付分配率；PUMP的烧毁估值/R仅是统计比较，UNI分母待核 |

7/30/90天的同口径经常性流量用 `窗口总额 × 365 / 天数` 折算为当前速度参考；完整365天窗口才表示过去一年的总额。两个统计比例不再年化，也不强制封顶100%。收入统计为零、负数或缺失时不生成P/S；UNI等估值字段仅生成注明性质的统计倍数，不补齐独立协议收入P/S。单日负收入仍应保留在窗口合计。亏损或净利润为零时项目净利润P/E不适用，净利润未知则保留未知。[SEC财务报表与P/E说明](https://www.sec.gov/about/reports-publications/beginners-guide-financial-statements)

净利润只能从经人工核对的 `profiles[].financials.net_income_windows[天数]` 读取，记录需包含 `usd`、`start`、`end`、`currency: USD`、`source_url`，并确认 `same_protocol_scope`、`costs_complete` 均为true。日期须与收入窗口完全一致。短窗折算需 `recurring_only: true`，避免把一次性利润放大；完整365天可以用该年度的完整净利润。成本应覆盖同一经济实体的激励、运营及其他应计费用；既有储备释放、回购和销毁不得自动当作经营费用扣除。未取得上述记录时保持P/E未知。当前采集器只接入 `dailyFees`、`dailyRevenue`、`dailyHoldersRevenue` 三类流量，没有接入净利润数据源，五项目快照也没有 `financials.net_income_windows`；页面因此显示“未接入净利润数据”。采集器不会自动生成净利润，也没有以默认成本率填数。未来接入记录后，期间、范围、成本完整性等校验仍然适用。

点击主表中的协议收入倍数、持币者回报倍数或项目净利润P/E单元格，可打开对应项目的算式、缺口和三条上游API/归档JSON；保存响应的哈希与逐日总额在浏览器中核对。原始字段有数据只代表该统计存在，不证明成本完整或利润已审计。

### 5.2 参考网站算法：已有统计能够计算的倍数

Crypto3D主表P/E是市值÷年化持币人回报，渲染用预计算收益率倒数；Net Inc展示列不参与这项除法。参考P/S同样用收入收益率倒数，UNI的收入字段实际使用dead转账的代币估值。完整净利润缺失只阻止5.1的净利润P/E，不阻止明确标注分母的参考倍数。[源码、JSON与两边差异](crypto3d-comparison.md)

本地主表将协议收入倍数P/S、持币者回报倍数、项目净利润P/E同时展示，估值固定为流通市值与CoinGecko的FDV，不设指标口径或FDV选择器。前两项由`calculateReferenceMultiples`使用统一观察窗口内完整的`holders.usd`和归一化`revenue.usd`，乘365/天数，再做估值除法；项目净利润P/E仍由`calculate`读取经核验净利润。前两项不读取参考站Net Inc，也不替代独立利润、独立收入语义。未知、明确缺日、非正分母不生成倍数，不回退其他窗口或原始重复额。JUP覆盖重叠仍披露；UNI表中P/S注明兑换估值，不用于计算收入分成率。

完整历史总额即使含库存事件，也能求历史统计倍数，但持币者回报倍数必须保留事件提示，不能称持续盈利预测。PUMP365天持币者回报倍数使用原始统计，收益率仍按经常性可年化部分处理；365天收入缺去重子项，P/S仍未知。HYPE跨销毁政策窗口的倍数不证明整个窗口已永久销毁。没有逐笔台账时，这些比例不证明现金回购或净通缩。

对照站数字从保存HTML、汇总及daily编译到独立证据文件；校验文件哈希、保留抓取时间与字段时点。这份证据及完整比较文档保留供按需复核，主表不再加载下方的大型对照解释框。其缺失短窗可能回退365天，Rev/Net Inc固定365天，和本地统一窗口不同。采用本地行情和窗口重算，不直接复制对照数字。

## 6. 政策变更的事件研究

每个政策保存公告日、投票日、执行交易、目标链生效日和会计确认日；时间线统计按UTC日，正文给出北京时间需要转换。使用事件前30/90日和事件后第1–30/90日，同类流量逐日完整，排除事件日；若后窗未结束则不计算。价格从事件前1日至事件后N日，保留每日时间戳，属于日频事件窗口近似，不是执行块瞬时成交。

比较收入、holder统计、真实burn币数、供应和相对 BTC/SOL/同业价格。UNI的兑换统计变化单列，不冒充营业收入变化；事件后窗遇到重复子项缺记录也应保留待核。`相对回报=(1+代币回报)/(1+基准回报)−1`，不是简单相减。营业收入前值0时“增长百分比”无定义，输出“0→正值”。CoinGecko公开一年价格窗无法支持2025-10前部分事件；缺价格不填0。[CoinGecko历史价格](https://docs.coingecko.com/reference/coins-id-market-chart)

供应变化不能由价格或市值涨跌推断。当前仅有一日供应快照，多年前事件的供应变动保留未知；从本次起归档日快照，后续再补burn/解锁合约历史。扩展收费覆盖、宏观市场、Meme热度、竞争及新产品会共同改变结果；本工具是描述性前后对比，不提供回购因果估计。

## 7. 每次复核与更新

1. 保存原始公开API响应、URL、抓取时间、响应/磁盘哈希和schema。失败沿用旧值但标明错误及滞后，不悄悄称最新。
2. 所有项目收入使用同一已完成UTC日作为截止；某项目缺日则对应窗口未知，不单独往前移动再比较。
3. 行情和供应采用同次快照，MC、FDV和价格保留供应商原值，亦提供 `p×supply`参考。禁止晚于历史研究日的估值进入回测。
4. 人工复核新的投票/执行/权限/比例/期限；采集器不自动把搜索到的提案变成有效政策。
5. 对实际回购、burn和储备释放做链上枚数与现金双账；检查bridge、存量、内部转账和重复listing。
6. 更新政策证据，给出已核实、仅政策文本、二级报道、模型假设、未知各自状态。
7. 用收入下降、买入价格变化、已知释放和可能治理增发重算压力情景；只有供给完备才给净供应结论。

政策、权利和现金证据优先于宣传年化值。
