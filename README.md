# 协议收入与代币价值研究框架

已接入 HYPE、PUMP、UNI、JUP、RAY、CAKE、BNB、AAVE 的研究与数据快照。当前数据快照：2026-10-03（北京时间）；机制与排期保留各自复核日期。工具只读取公开研究数据，无交易功能。

## 打开

当前预览：[本地仪表盘](http://127.0.0.1:8765/web/)。如果服务已结束，在此文件夹双击 `启动研究框架.command`，再打开上述链接。

或在终端运行：

```sh
python3 scripts/serve.py
```

只依赖系统已有 Python 3；网页无第三方依赖。页面需要通过本地服务打开，不能直接双击 HTML。

## 按需加载与部署

默认展示最近30天，首屏只读取 `data/dashboard-lite.json`，其中包含最近90天的图表点及全部代币的汇总指标。点击“更多时间段”后可选1/3/5年，也可直接使用自定义日期。更早图表只下载当前代币与所选日期相交的年份文件；切换代币时再补该代币的历史。已加载的文件复用，不预先下载全部多年历史。

自定义日期和3/5年窗口的费用归一化在模块 Web Worker 中执行，不占用页面渲染线程；原始来源在首次需要时读取，之后复用。尚未加载显示加载状态，失败可重试；真正缺日继续显示未知，不补零。所有历史片及归档来源仍核验本次快照登记的SHA256。

首次五币版本的性能检查（2026-10-03）：完整文件8,593,772字节，首屏轻量文件443,430字节，减少94.84%；本地服务gzip后的首屏数据实际传输92,129字节。此处仅计数据文件，不包含HTML/脚本/样式，也不是所有设备或网络下的加载时间承诺。完整快照、原始响应与来源记录保留。

本次八币快照（2026-10-03）：完整文件17,035,417字节，首屏轻量文件1,038,810字节，gzip后175,808字节；更多年份仍在用户选择后按需下载。

`refresh.py` 每次更新同时生成轻量快照和按代币/年份拆分的历史文件。仅重新拆分已有快照，无网络请求：

```sh
python3 scripts/web_assets.py
```

静态部署需保留 `web/`、`data/dashboard-lite.json`、`data/web/`、`data/responses/` 和链接到的 `research/` 相对目录，并使用HTTPS（本地回环地址也可核验数据）。本地 `serve.py` 已提供gzip、ETag和条件请求；其他服务器需配置相同策略：HTML/脚本/样式及固定轻量快照使用 `Cache-Control: no-cache`，包含完整内容哈希的历史/来源文件使用 `public, max-age=31536000, immutable`，文本与JSON开启压缩。固定快照最后发布，已被旧快照引用的哈希文件保留，避免更新中断正在浏览的页面。

## 看什么

- 页面上方的总结表始终列出全部研究代币，并显示代币总数；选择一个代币不会筛掉其他表格行。
- 统一时间筛选放在总结表之前：7/30/90天，点“更多时间段”展开1/3/5年，另有“自定义”。总结表之后保留代币下拉选择和默认折叠的未来供应对比；详情默认收起。自定义按起止两个完整UTC日筛选；窗口同步更新总结表、收入去向图、历史图和结论，选币只决定其后的详情。3/5年快捷项分别为1095/1825天，具体日期直接显示。
- 点击总结表的数值表头排序：首次从高到低，再次点击反向；名称按字母顺序。年化收益率及倍数主表头按流通市值，表头内“按FDV”按钮按标有FDV的指标排序。排序使用原始数值，缺失与不适用始终置后，同值保持原顺序；切换时间后保留排序条件并重算，仅重排总结表。点击“默认顺序”恢复原项目顺序。
- 主表 FDV 固定使用 CoinGecko 返回的 `fully_diluted_valuation`，无需选择三种口径。项目“FDV与供应量估值”折叠详情保留“价格 × 数据源总量”和“价格 × 初始分配量”两项参考计算；它们不作为主表收益率或倍数的分母。
- 点击代币后，详情分为收入流向、供应与解锁、历史与政策、数据来源、分析结论五个页签；历史图表在打开对应页签后才渲染和加载。收入流向页展示资金路径，金额随统一观察窗口更新。收入按业务拆分，实线标同窗统计关系，虚线标政策或未对账路径。业务构成、节点解释与口径限制默认折叠；展开图下方可查看在线 API、本次 JSON、抓取时间和去重依据。
- 使用代币下拉，或点击总结表的对应项目行作为快捷入口，查看该代币的收入来源、回购去向、供应分配与完整性；表格选择与下拉同步，详情只展示当前选择的代币。
- 主表最右列“来源”可查看本次 API 返回、抓取时间、接口字段、逐日金额与重算结果；“在线 API”打开上游实时接口，与本次快照分开。保存响应按文件哈希归档到 `data/responses/`，以后更新不会替换已归档的证据。
- 主表并排显示P/S与持币者回报倍数；收入占手续费、回购/销毁占收入保留在财务详情和收入图中。表头公式、重复时间说明与年化解释集中到“指标说明”，每行来源收为一个按钮。宽屏保留未来365天释放列；1200px以下通过折叠的供应对比查看，优先让估值指标完整展示。P/S使用年化收入统计，未扣完整经营成本，UNI注明兑换估值；持币者回报倍数使用年化回购／销毁等holder统计。未接入数据的项目净利润P/E列已移除；当前采集器仅接入手续费、协议收入和持有人回报三类流量。每个数值旁都标出“流通市值”或“FDV”；两种估值使用同一份年化金额，FDV考虑尚未流通的供应且采用CoinGecko口径。点击倍数查看算式、缺口和原始响应。
- “持币者回报”是指向代币的回购、销毁或分配统计，不表示持币者实际收到等额现金；它也不等于项目净利润。
- 展开“全部代币 · 供应对比”，查看“总量、流通与未来释放”横表中的未来30/90/365天部分计划或估算；这些列按已注明类别披露，不是完整流通预测。CAKE约8.12M/年是净有效排放政策情景，AAVE约54,750/年是须补资的旧储备奖励速度情景，BNB常规新发行0也不代表储备释放0。当前代币明细保留下一事件日期、证据级别、已到期未领余额、库存和缺口。未来预测期与历史观察窗口分别标示。
- 时间线比较公告或执行前后 30 / 90 天的收入、价格与 BTC / SOL 表现。缺历史供应快照明确留空。
- 所选代币详情的最后一个页签为“分析结论”：先展示加粗的研究判断；点击“展开完整分析”查看收入来源与周期风险、指向代币的统计比例、流通/总量/FDV、历史分配、未来90天部分释放、净供应判断条件、两种估值分母的年化回购/销毁规模，以及政策变更与固定事件前后30天对照。数值随窗口和快照更新；研究判断、机制及排期仍需人工复核。“查看结论依据与时间口径”可展开来源和时间说明。缺台账不宣称已核净通缩，库存事件不强行年化，UNI费用兑换估值不冒充营业收入。

表中的“年化回购／销毁收益率”按年化回购／销毁统计金额除以流通市值及FDV，使用 DefiLlama `dailyHoldersRevenue`，收入型项目分别统计费用分配、回购额度或销毁估值；BNB另用公开销毁记录，不混入这条收入统计。它不是统一口径的实际现金回购排名。PUMP 的费用与收入剔除重复移动端；一年窗口缺首日去重子项，收入与P/S未知，且跨存量销毁事件尚未对账，收益率停止年化；持币者回报倍数可显示历史总额倍数并注明库存事件。UNI的API revenue复制费用兑换UNI估值，表中P/S因此注明兑换估值，独立协议收入仍未知；HYPE跨永久销毁政策的窗口不套用当前burn分类。

FDV、总量与最大供应量是上游接口的不同字段，主表不强行把FDV重算为“价格 × 最大供应量”。参考计算中的数据源总量是CoinGecko的 `total_supply`，并非本工具独立审计的经济有效供应；初始分配量来自项目研究，亦不保证是未来永久上限。[CoinGecko字段文档](https://docs.coingecko.com/reference/coins-markets)

## 更新

已配置本研究对话每天北京时间 04:00 的本地自动更新。运行条件、自动数据与人工复核的分界、dot 交接说明见 [每日更新](research/daily-update.md)。目前尚未迁到 dot 的云端电脑；不要把本地计划视为已完成云端接管。

```sh
python3 scripts/refresh.py
```

更新公开收入、当前行情和历史价格，保留原始 JSON、来源 URL、抓取时间、原始响应 SHA256 和归档快照。收入不再截为最近两年，保存上游完整可用历史。CoinGecko一年价格保留原值，更早部分接入DeFiLlama价格API：从2020年起按币种组和70日分块，每次不超过500个价格点；新增币种另分组，保留原七币请求的缓存，复用已完成块，仅更新变化的末块和失败块；UTC零点±1小时匹配，保存真实时间与来源，缺日不插值。收入只纳入刷新开始时实际已结束的 UTC 日；北京时间凌晨 4 点不会计入尚未结束的前一个 UTC 日。CoinGecko请求统一排队，线程间至少间隔4秒；收到HTTP 429后，其他线程也遵守同一冷却时间。按上游Retry-After有界等待并重试一次；仍失败时保留旧值、真实日期及错误信息，页面注明受影响代币、接口、原因和上次成功时间。未来窗口按新研究日重算，但排期依据仍是手工复核的政策；采集器不自动修改经济机制、分配或解锁政策。

2026-10-03曾出现的单一刷新错误来自AAVE的CoinGecko历史价格接口，返回HTTP 429，并非BNB。当时保留了上一份成功响应；本轮针对该接口重试已成功。请求间隔和冷却可减少限流冲突，但不保证上游始终可用。

“历史数据覆盖与价格来源”列出各字段实际起止、缺日及补充价格的归档JSON。[历史数据说明](research/history-data.md)记录各币实际起点、采样与刷新方式。自定义窗口由本次归档响应核验哈希后重建，沿用费用去重、已确认政策前零、库存事件和完整性限制；早于协议有记录的日期不填零。历史收入除以当前市值/FDV是当前估值与该期间平均流量的对照，不是历史估值回测；供应量和未来排期也不随历史截止日倒退。

仅重新计算已有数据：

```sh
python3 scripts/refresh.py --offline
```

历史回测需要当时的市场快照。本采集器拒绝使用晚于 `--as-of` 的行情；归档目录提供未来重建历史供应和估值的基础，尚未实现全历史链上重放。

参考站对照由已保存网页、汇总JSON和daily证据离线复算：`python3 scripts/compare_crypto3d.py`。重新抓取并审查来源后才能更新这份证据；不把其Net Inc直接导入为独立净利润。

CAKE与AAVE使用DeFiLlama的完整费用、收入及持币者统计，并保留实际现金支出或实际销毁尚未对账的说明。AAVE买回币进入生态储备，可重新分发，回购不等于永久销毁；暂停事件按日期登记，最新窗口不套用旧预算。CAKE保留增发与销毁台账缺口，不凭回购额度判断净通缩。未来释放详见[CAKE/AAVE核验](research/supply-cake-aave.md)：净有效排放不能填成gross mint，旧储备奖励不能填成new mint。原五币排期复核日保留2026-10-02，新三币为2026-10-03；随窗口重算不会自动推进政策复核日期。

BNB独立展示季度销毁完整历史、BSC链手续费与Gas销毁估算。本轮保存第1至36次已执行季度记录：第1至7次通过Ethereum交易、收据、Burn事件和区块时间独立核验，第27至36次通过BSC交易、收据和区块时间独立核验；第8至26次取回官方Beacon浏览器的交易索引记录，标为“浏览器索引确认”，不冒充独立RPC核验。全部36期另经官方公告复核，`data/bnb-quarterly-history.json`登记公告总额、拆分、发布时间及40份官方原始响应的SHA256。页面区分公告总额与链上实际数量，保留Pioneer、额外销毁、日期和舍入差异；公告日期不替代执行日期。第37、38次预测不计入已发生历史。详见[BNB历史来源核验](research/bnb-historical-source-review.md)。

日更使用BNB Chain官方推荐的社区`bnbburn.info`接口发现新季度，再按发生链取证；它是索引，不是最终链上账本，也没有在此承诺长期可用性。已完成季度的交易证据按来源、请求和响应哈希校验后复用，保留原核验时间，避免每天重复请求全部历史；RPC失败或结果不完整时，依次尝试脚本登记的备用节点，保存实际成功节点及错误记录。36期官方公告是本次复核的静态归档，新季度公告和经济机制仍需人工审核，日更不会自动将其标为已复核。

季度销毁美元值使用该交易UTC日的已保存采样价格，是估值而非币安现金支出。链手续费来自真实交易Gas索引，并由供应商换算美元；仅覆盖BSC，不是币安企业收入。Gas日销毁金额是供应商按手续费固定10%计算的模型，尚非逐日`feeBurned`实际台账；单一区块读取的`burnRatio()`与比例尺度只证明当时参数，不能反推整个历史窗口比例。跟踪器累计和滚动7天摘要继续单独展示，不摊成每日或与季度记录宣称完整实际合计。已探测的公共dataseed禁用或限制`eth_getLogs`，完整Gas销毁历史日志仍是缺口。BNB不计算币安项目利润P/E、收入P/S或收入回购率，已核季度销毁比例不年化。原始接口和RPC证据按哈希归档，[数据核验记录](research/bnb-data-review.json)保留来源、方法与限制。

新增项目需同时修改 `data/profiles.json`、`scripts/refresh.py` 中的币种 ID 和父协议 slug，并按 [研究口径](research/framework.md) 完成证据登记。不能只写一个宣传比例。
